# 程序员 · AI 工作流（5 大核心任务）

## 任务1：代码审查

### 📌 任务定义
- **场景描述**：PR评审、代码质量检查、安全审查
- **输入要求**：代码变更、审查标准、关注点
- **输出标准**：结构化审查意见

### 🤖 SOLO工作流
1. **代码阅读**：阅读代码变更
2. **标准对照**：对照编码规范审查
3. **问题识别**：识别代码问题
4. **建议输出**：给出改进建议
5. **学习沉淀**：提炼可复用经验

### 💡 最优Prompt
```
作为资深工程师，请帮我审查代码。

【代码信息】
- 语言/框架：{如Python/Java/React}
- 变更类型：{新功能/Bug修复/重构}
- 代码规模：{约多少行}

【代码内容】
```
{粘贴代码}
```

【审查重点】
请从以下维度审查：
1. 代码质量（可读性、可维护性）
2. 设计模式（架构合理性）
3. 性能考虑（性能瓶颈、资源使用）
4. 安全问题（安全漏洞、敏感信息）
5. 测试覆盖（单元测试、边界情况）
6. 最佳实践（编码规范、惯用法）

请输出：
1. 总体评价
   - 评分（1-10）
   - 核心问题
   - 亮点

2. 详细审查意见
   | 行号 | 问题类型 | 问题描述 | 建议修改 | 严重程度 |
   |------|----------|----------|----------|----------|
   | {行号} | {类型} | {问题} | {建议} | {高/中/低} |

3. 必须修改（高优先级）
   - 问题：{描述}
   - 建议：{具体修改建议}
   - 示例代码：{如有}

4. 建议优化（中优先级）

5. 可选改进（低优先级）

6. 学习要点

格式：Markdown，建议具体可执行。
```

### 📈 提效数据
- **传统耗时**：1-2小时
- **AI辅助耗时**：15-30分钟
- **效率提升**：75%
- **质量提升**：问题发现率提升40%，代码质量提升

---

## 任务2：技术方案设计

### 📌 任务定义
- **场景描述**：新功能开发、系统重构、技术选型
- **输入要求**：需求描述、技术约束、性能要求
- **输出标准**：完整技术设计文档

### 🤖 SOLO工作流
1. **需求分析**：分析功能和非功能需求
2. **方案调研**：调研技术方案选项
3. **架构设计**：设计系统架构
4. **详细设计**：设计关键模块和接口
5. **风险评估**：评估技术风险

### 💡 最优Prompt
```
作为架构师，请帮我设计技术方案。

【需求背景】
- 项目名称：{项目名称}
- 需求描述：{功能需求描述}
- 业务场景：{使用场景}

【技术约束】
- 技术栈：{如Java/Spring/MySQL/Redis}
- 部署环境：{如云原生/容器化}
- 集成系统：{需要对接的系统}

【非功能需求】
- 性能要求：{如QPS、响应时间}
- 可用性要求：{如99.9%}
- 数据规模：{数据量级}

请输出技术设计文档：
1. 概述
   - 背景
   - 目标
   - 范围

2. 总体设计
   - 架构图（Mermaid格式）
   - 技术选型及理由
   - 核心流程

3. 详细设计
   - 数据模型设计
   - 接口设计（API定义）
   - 核心模块设计
   - 关键算法

4. 非功能设计
   - 性能方案
   - 可扩展性设计
   - 安全设计
   - 监控告警

5. 风险评估
   - 技术风险
   - 缓解措施

6. 实施计划
   - 开发排期
   - 里程碑

格式：Markdown，包含Mermaid图表。
```

### 📈 提效数据
- **传统耗时**：8-20小时
- **AI辅助耗时**：2-3小时
- **效率提升**：85%
- **质量提升**：设计更全面，风险识别更准确

## 任务3：Bug修复分析

### 📌 任务定义
- **场景描述**：线上问题排查、Bug定位、根因分析
- **输入要求**：问题描述、日志信息、复现步骤
- **输出标准**：问题分析报告 + 修复方案

### 🤖 SOLO工作流
1. **问题复现**：确认问题复现步骤
2. **日志分析**：分析相关日志信息
3. **根因定位**：定位问题根因
4. **修复方案**：设计修复方案
5. **预防措施**：制定预防措施

### 💡 最优Prompt
```
作为故障排查专家，请帮我分析Bug并给出修复方案。

【问题描述】
- 问题现象：{描述问题表现}
- 影响范围：{影响用户/功能}
- 发现时间：{时间}

【环境信息】
- 运行环境：{如生产/测试}
- 技术栈：{语言/框架/中间件}
- 版本信息：{相关版本}

【复现步骤】
{描述如何复现问题}

【日志信息】
```
{粘贴相关日志}
```

【相关代码】
```
{粘贴相关代码片段}
```

请输出：
1. 问题分析
   - 问题定位
   - 根因分析
   - 影响评估

2. 修复方案
   - 修复思路
   - 代码修改建议
   - 修复后验证方法

3. 临时方案（如需要）

4. 预防措施
   - 代码层面
   - 测试层面
   - 监控层面

5. 知识沉淀
   - 问题归类
   - 经验总结

格式：Markdown，分析清晰，方案可执行。
```

### 📈 提效数据
- **传统耗时**：2-8小时
- **AI辅助耗时**：30分钟-1小时
- **效率提升**：80%
- **质量提升**：定位更快，修复更彻底

## 任务4：API文档编写

### 📌 任务定义
- **场景描述**：接口文档、SDK文档、集成指南
- **输入要求**：接口定义、参数说明、示例代码
- **输出标准**：完整API文档

### 🤖 SOLO工作流
1. **接口梳理**：梳理所有接口
2. **文档结构**：确定文档结构
3. **内容编写**：编写接口详细说明
4. **示例补充**：补充请求/响应示例
5. **错误码整理**：整理错误码说明

### 💡 最优Prompt
```
请帮我编写API接口文档。

【接口信息】
- 接口名称：{接口名称}
- 接口地址：{URL}
- 请求方式：{GET/POST/PUT/DELETE}
- 接口描述：{功能描述}

【请求参数】
{参数列表，如：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | int | 是 | 用户ID |
}

【响应参数】
{响应字段说明}

【业务逻辑】
{接口的业务逻辑说明}

请输出完整API文档：
1. 接口概述
   - 功能说明
   - 使用场景

2. 请求说明
   - 请求地址
   - 请求方式
   - 请求头
   
3. 请求参数
   | 参数名 | 类型 | 必填 | 说明 | 示例 |
   |--------|------|------|------|------|
   
4. 响应说明
   - 响应格式
   - 响应参数
   | 字段名 | 类型 | 说明 |
   |--------|------|------|
   
5. 请求示例
   ```json
   {请求示例}
   ```

6. 响应示例
   ```json
   {响应示例}
   ```

7. 错误码说明
   | 错误码 | 说明 | 处理建议 |
   |--------|------|----------|

8. 注意事项

格式：Markdown，符合OpenAPI规范风格。
```

### 📈 提效数据
- **传统耗时**：1-2小时/接口
- **AI辅助耗时**：15-20分钟/接口
- **效率提升**：80%
- **质量提升**：文档更规范，对接效率提升50%
