# 产品经理 · AI 工作流（5 大核心任务）

## 任务1：需求文档撰写（PRD）

### 📌 任务定义
- **场景描述**：新功能开发、产品迭代、需求变更时
- **输入要求**：业务目标、用户反馈、竞品信息、技术约束
- **输出标准**：完整PRD文档（背景-目标-方案-验收标准）

### 🤖 SOLO工作流
1. **信息收集**：整理业务需求、用户调研数据、技术可行性
2. **框架搭建**：使用AI生成PRD基础框架
3. **内容填充**：逐章节完善需求细节
4. **评审优化**：AI辅助检查逻辑漏洞和遗漏点
5. **格式规范**：生成标准文档格式

### 💡 最优Prompt
```
你是一位资深产品经理，请帮我撰写一份完整的PRD文档。

【产品背景】
- 产品名称：{产品名称}
- 版本号：{版本号}
- 目标用户：{目标用户群体}

【业务目标】
{描述本次迭代要解决的核心问题和业务价值}

【需求来源】
- 用户反馈：{具体反馈内容}
- 数据支撑：{相关数据指标}
- 竞品分析：{竞品参考}

【功能范围】
{列出本次涉及的功能模块}

请按以下结构输出：
1. 文档信息（版本记录、修订历史）
2. 背景与目标
3. 用户故事与场景
4. 功能需求详述
5. 非功能需求
6. 数据埋点需求
7. 验收标准
8. 风险评估

要求：逻辑清晰、可执行性强、开发可直接使用。
```

### 📈 提效数据
- **传统耗时**：4-8小时
- **AI辅助耗时**：45-60分钟
- **效率提升**：85%
- **质量提升**：结构更完整，遗漏率降低60%

## 任务2：竞品分析报告

### 📌 任务定义
- **场景描述**：产品规划、市场定位、功能迭代前
- **输入要求**：竞品名单、分析维度、关注重点
- **输出标准**：结构化竞品分析报告

### 🤖 SOLO工作流
1. **竞品筛选**：确定分析对象（直接竞品/间接竞品/潜在竞品）
2. **维度设计**：确定分析框架（功能/体验/商业模式/运营策略）
3. **信息采集**：AI辅助收集整理竞品信息
4. **对比分析**：生成对比表格和差异分析
5. **结论输出**：提炼可借鉴点和差异化方向

### 💡 最优Prompt
```
作为产品分析专家，请帮我完成一份竞品分析报告。

【分析对象】
- 我方产品：{产品名称} - {一句话定位}
- 竞品A：{名称} - {定位}
- 竞品B：{名称} - {定位}
- 竞品C：{名称} - {定位}

【分析维度】
请从以下维度进行深度对比：
1. 产品定位与目标用户
2. 核心功能对比（功能矩阵表）
3. 用户体验与交互设计
4. 商业模式与盈利方式
5. 运营策略与增长手段
6. 技术架构与性能表现
7. 市场份额与用户口碑

【输出要求】
1. 每个维度生成对比表格
2. 标注我方优劣势
3. 提炼3-5个可借鉴点
4. 给出差异化建议

格式：Markdown，包含表格和图表建议。
```

### 📈 提效数据
- **传统耗时**：8-16小时
- **AI辅助耗时**：2-3小时
- **效率提升**：80%
- **质量提升**：分析维度更全面，洞察深度提升40%

## 任务3：产品路线图规划

### 📌 任务定义
- **场景描述**：季度规划、年度战略、版本排期
- **输入要求**：业务目标、资源情况、技术依赖、市场节奏
- **输出标准**：可视化路线图 + 详细说明文档

### 🤖 SOLO工作流
1. **目标拆解**：将年度目标拆解为季度里程碑
2. **需求池整理**：功能点优先级排序
3. **资源评估**：评估开发资源和时间窗口
4. **版本规划**：确定各版本功能范围
5. **风险预案**：识别关键路径和风险点

### 💡 最优Prompt
```
作为产品规划专家，请帮我制定产品路线图。

【产品信息】
- 产品名称：{产品名称}
- 当前版本：{当前版本}
- 规划周期：{时间范围，如2024Q1-Q4}

【业务目标】
- 年度GMV目标：{目标}
- 用户增长目标：{目标}
- 其他关键指标：{目标}

【需求池】
{列出待规划的功能需求，标注优先级P0/P1/P2}

【资源情况】
- 研发团队规模：{人数}
- 发布节奏：{如双周迭代}
- 关键时间节点：{如618、双11等}

【技术依赖】
{列出需要等待的技术基建或外部依赖}

请输出：
1. 季度里程碑规划表
2. 版本功能范围说明
3. 关键路径图示（Mermaid格式）
4. 资源分配建议
5. 风险识别与应对措施
```

### 📈 提效数据
- **传统耗时**：6-12小时
- **AI辅助耗时**：1-2小时
- **效率提升**：85%
- **质量提升**：规划更系统，风险识别更全面

## 任务4：用户故事拆解

### 📌 任务定义
- **场景描述**：需求评审前、迭代规划时、开发估时前
- **输入要求**：功能需求、用户场景、验收条件
- **输出标准**：标准用户故事卡片 + 任务拆解

### 🤖 SOLO工作流
1. **场景梳理**：识别所有用户场景和角色
2. **故事编写**：按"作为...我想要...以便..."格式
3. **验收条件**：定义清晰的AC（Acceptance Criteria）
4. **任务拆解**：将故事拆解为开发任务
5. **估时建议**：提供工时评估参考

### 💡 最优Prompt
```
作为敏捷开发专家，请帮我将功能需求拆解为用户故事。

【功能需求】
{描述功能需求内容}

【用户角色】
{列出涉及的用户角色，如普通用户、VIP用户、管理员等}

【拆解要求】
1. 按INVEST原则拆分
2. 每个故事控制在1-3天工作量
3. 明确验收条件（Given-When-Then格式）
4. 标注故事间依赖关系

请按以下格式输出：

## Epic: {史诗名称}

### Story 1: {故事标题}
- **作为**：{用户角色}
- **我想要**：{功能描述}
- **以便**：{业务价值}

**验收条件**：
- Given {前置条件}
- When {触发动作}
- Then {预期结果}

**开发任务**：
- [ ] 任务1：{任务描述}（预估：X小时）
- [ ] 任务2：{任务描述}（预估：X小时）

**依赖**：{依赖的其他故事或技术模块}
```

### 📈 提效数据
- **传统耗时**：2-4小时
- **AI辅助耗时**：20-30分钟
- **效率提升**：85%
- **质量提升**：故事拆分更合理，验收条件更清晰

## 任务5：数据分析报告

### 📌 任务定义
- **场景描述**：功能上线后评估、周/月度复盘、问题诊断
- **输入要求**：数据指标、时间范围、对比维度
- **输出标准**：数据报告 + 洞察结论 + 行动建议

### 🤖 SOLO工作流
1. **指标定义**：明确核心指标和过程指标
2. **数据提取**：获取原始数据
3. **分析框架**：AI辅助构建分析维度
4. **洞察提炼**：发现数据异常和趋势
5. **建议输出**：给出可执行的行动建议

### 💡 最优Prompt
```
作为数据分析专家，请帮我分析以下数据并输出报告。

【分析背景】
- 分析目的：{如功能上线效果评估/问题诊断/趋势分析}
- 时间范围：{开始日期} 至 {结束日期}
- 对比基准：{如上周/上月/去年同期}

【核心数据】
{粘贴数据表格或描述数据情况}

【分析维度】
请从以下角度分析：
1. 整体趋势：核心指标变化趋势
2. 结构分析：各维度占比和变化
3. 漏斗分析：转化漏斗各环节表现
4. 异常识别：数据异常点和可能原因
5. 归因分析：影响指标变化的关键因素

【输出要求】
1. 执行摘要（3-5条核心结论）
2. 详细分析（含数据可视化建议）
3. 问题诊断
4. 行动建议（优先级排序）

格式：Markdown，包含表格。
```

### 📈 提效数据
- **传统耗时**：4-8小时
- **AI辅助耗时**：1-1.5小时
- **效率提升**：80%
- **质量提升**：分析维度更全面，洞察深度提升50%
